# 不等式约束传递测试分析

## 概述

本测试套件验证 Oracle 和 PostgreSQL 优化器在处理不等式约束时的范围推理能力。通过设计多种场景的查询，观察优化器如何利用约束条件进行范围推理，从而优化查询执行计划。

## 测试场景

### 1. 基本不等式约束推理
- **目标**: 验证优化器能否从 `A < B` 和 `B >= C` 推理出 `A < C`
- **示例**: `c.registration_date < o.order_date AND o.order_date >= '2023-02-01'`
- **期望**: 优化器应推理出 `c.registration_date < '2023-02-01'`

### 2. 多表连接的范围推理
- **目标**: 测试多表连接中约束的传播能力
- **示例**: 三表连接中的链式约束推理
- **期望**: 优化器应能推理出所有相关表的范围限制

### 3. BETWEEN 约束的推理
- **目标**: 验证 `BETWEEN` 条件的推理能力
- **示例**: `o.total_amount BETWEEN 1000 AND 2000 AND c.credit_limit >= o.total_amount`
- **期望**: 推理出 `c.credit_limit >= 1000`

### 4. 复杂不等式链式推理
- **目标**: 测试多层约束的链式推理
- **示例**: 多个不等式条件的组合推理
- **期望**: 优化器应能处理复杂的约束链

### 5. 函数约束的推理
- **目标**: 测试包含函数的约束条件
- **示例**: `EXTRACT(YEAR FROM o.order_date) = 2023`
- **期望**: 优化器应能处理函数约束

### 6. 子查询中的约束推理
- **目标**: 验证子查询约束对外层查询的影响
- **示例**: 相关子查询中的约束推理
- **期望**: 子查询约束应能影响外层查询的计划

### 7. 分区表的约束推理
- **目标**: 测试分区裁剪与约束推理的结合
- **示例**: 分区表上的范围查询
- **期望**: 结合约束推理进行分区裁剪

### 8. 统计信息依赖
- **目标**: 验证统计信息对约束推理的影响
- **示例**: 有无统计信息时的计划差异
- **期望**: 统计信息应影响约束推理的准确性

### 9. 性能影响
- **目标**: 测量约束推理对查询性能的影响
- **示例**: 比较有无约束推理的查询性能
- **期望**: 约束推理应提升查询性能

### 10. 边界情况
- **目标**: 测试空结果集、NULL值等边界情况
- **示例**: 未来日期查询、NULL值处理
- **期望**: 优化器应正确处理边界情况

## PostgreSQL 特有测试

### 11. 约束排除
- **目标**: 测试 PostgreSQL 的约束排除优化
- **示例**: 带 CHECK 约束的表查询
- **期望**: 利用约束排除优化查询

### 12. 表达式索引的约束推理
- **目标**: 测试基于表达式的约束推理
- **示例**: `EXTRACT(YEAR FROM order_date)` 索引
- **期望**: 优化器应能利用表达式索引

### 13. 部分索引的约束推理
- **目标**: 测试部分索引对约束推理的影响
- **示例**: 带 WHERE 条件的部分索引
- **期望**: 部分索引应影响约束推理

### 14. 多列约束的推理
- **目标**: 测试复合约束条件的推理
- **示例**: 多列索引上的约束推理
- **期望**: 优化器应能处理复合约束

### 15. 窗口函数的约束推理
- **目标**: 测试窗口函数中的约束推理
- **示例**: 带窗口函数的约束查询
- **期望**: 窗口函数不应影响约束推理

## 预期结果

### Oracle
- 强大的约束推理能力，能处理复杂的约束链
- 基于统计信息的精确范围估计
- 良好的分区裁剪与约束推理结合

### PostgreSQL
- 基础的约束推理能力
- 约束排除优化
- 表达式索引和部分索引的支持

## 分析方法

1. **执行计划分析**: 通过 `EXPLAIN` 查看优化器是否利用了推理出的约束
2. **索引使用**: 观察是否选择了合适的索引
3. **连接顺序**: 检查是否基于约束推理优化了连接顺序
4. **分区裁剪**: 验证是否进行了有效的分区裁剪
5. **性能测量**: 比较有无约束推理的查询性能

## 注意事项

1. **统计信息**: 确保表统计信息是最新的
2. **索引设计**: 合理设计索引以支持约束推理
3. **数据分布**: 测试数据应能体现约束推理的效果
4. **版本差异**: 不同版本的优化器能力可能有差异
